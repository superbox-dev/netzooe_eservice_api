# AGENTS.md

Async Python client (`aiohttp`) for the unofficial Netz Oberösterreich eService portal API (`eservice.netzooe.at`).
Published on PyPI and used by the Home Assistant integration, so the public API must stay backwards compatible.

## Setup and commands

The project uses `uv`. Always run tools through `uv run`.

```bash
./scripts/setup.sh                   # uv sync --locked --dev + prek hooks
uv run pytest                        # tests (parallel, coverage, stops at first failure)
uv run pytest --snapshot-update      # regenerate syrupy snapshots in tests/__snapshots__/
uv run ruff format                   # format
uv run ruff check --fix              # lint (select = ALL)
uv run ty check                      # type check (warnings are errors)
uv run rumdl check --fix             # Markdown lint
uv run yamllint .                    # YAML lint
./scripts/lint.sh                    # all linters at once
```

Before you finish a change, run `./scripts/lint.sh` and `uv run pytest`. CI runs both on Python 3.13 and 3.14.

## Hard rules

- **100% test coverage is enforced** (`fail_under = 100`). Every new code path needs a test.
- **Python 3.13 is the minimum.** Do not use syntax or stdlib features from newer versions.
- **Line length 120**, single-line imports (`force-single-line`), full type annotations.
- **Docstrings use NumPy style.** Tests are exempt from docstring rules.
- Prefer fixing a lint error over adding `# noqa`. If a `noqa` is needed, use the specific rule code.
- Never edit `netzooe_eservice_api/version.py`. It is generated by `setuptools-scm`.
- Never use real credentials or real customer data (contract account numbers, meter point numbers, ...) in code,
  tests, snapshots or docs. Use placeholders like `"test"`.
- **No breaking changes to anything that can be used externally**: public methods of `NetzOOEeServiceAPI`, their
  signatures and return values, `Pod`, constants, enum members, exceptions and behaviour that worked before.
  If a rename is needed, keep the old name as an alias and note it in the changelog. New parameters must be
  optional with a default that keeps the old behaviour. Internal code (`_`-prefixed methods) may change.
  A crash (e.g. `KeyError`, an uncaught `aiohttp` exception) may become an `APIError`, but a call that worked must
  keep working.

## Architecture

- `netzooe_eservice_api/api.py`: `NetzOOEeServiceAPI`, the entry point, and the `Pod` `TypedDict`.
  - `login()` posts to `/service/j_security_check`, then `GET /service/v1.0/session` sets the `XSRF-TOKEN`
    cookie that is sent as `x-xsrf-token` header on every request.
  - `_request()` logs in lazily if there is no token, retries once after a re-login on `401` and maps errors:
    invalid JSON (e.g. the maintenance page) → `InvalidJsonError`, `401` → `AuthenticationError`,
    other status codes and `aiohttp.ClientError` → `APIError`.
  - Session handling: a passed `session` is never closed by the client. If no session is passed, the client
    creates its own and closes it on `logout()` and on errors (`_close_session()`).
  - Public methods (`dashboard`, `consents`, `consumptions_profiles`, `contract_accounts`, `consumptions_profile`)
    use `_get` / `_post` and return the raw JSON (`dict[str, Any]` / `list[dict[str, Any]]`).
- `netzooe_eservice_api/constants.py`: portal URLs (`ESERVICE_PORTAL`, `ESERVICE_PORTAL_API`), `COMMON_HEADERS`
  and the `Enum`s for query/body values (`ConsentsStatus`, `ConsumptionsProfilesBranch`, `ConsumptionsDimension`,
  ...). Enum values are the exact strings the portal expects.
- `netzooe_eservice_api/error.py`: exceptions (`APIError`, `InvalidJsonError`, `AuthenticationError`).

API conventions:

- The public Python API uses `snake_case`. Map to the portal's `camelCase` keys inside the method
  (see `consumptions_profile()` and `Pod`). Optional fields are only sent when they are set.
- Parameters that accept enum values take a single member, a list of members or `None` (see `consents()`).

## Adding or changing an endpoint

1. Add any new enum or constant to `constants.py`.
2. Add the public method to `NetzOOEeServiceAPI` in `api.py` with a NumPy docstring. Use `_get` / `_post`.
3. Add happy-path and unhappy-path tests in `tests/test_api.py`. Mock HTTP with `aioresponses`
   (use `create_client` / `create_logged_in_client`) and assert the recorded requests with the `snapshot` fixture.
   Run `uv run pytest --snapshot-update` and review the diff in `tests/__snapshots__/test_api.ambr`.
4. Update the usage example in `README.md` if the change is relevant for users.
5. Add an entry under `## [Unreleased]` in `CHANGELOG.md`.

## Changelog and git

- `CHANGELOG.md` follows Keep a Changelog (`Added` / `Changed` / `Fixed` / `Security` ...). Write in past tense
  ("Added ...", "Fixed ..."), wrap identifiers in backticks and link issues as `([Issue #67][issue-67])`.
  Every user-visible change needs an entry. Internal refactors that don't change behaviour don't.
- Development happens on `develop`. `main` is the release branch. Releases are created from `v*` tags
  (`vX.Y.ZbN` = pre-release) and published to PyPI by CI.
- Only commit or push when asked. Don't update `coverage-badge.svg` by hand, CI regenerates and commits it.
